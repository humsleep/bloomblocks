# 마을 V1 — 시스템·장면 골격 진행 기록 (Frontend, 2026-10-17)

범위: 오너가 정한 **1.0 4주 축소판**(DECISIONS.md 마지막 절). 주민 5명(Wick·Momo 0일, Sage 2, Luna 4, Pip 7), 가구 12종 × 색 2–3, 방 꾸미기, 선물·편지, 대사 약 60줄.
1.1로 넘긴 것(데이터 모델만 확장 가능하게 두고 UI는 만들지 않음): 실시간 시간대·계절, 장터, 부탁, 방 엽서, 주민 6·7번째.
그림 계약: `docs/team/village-contract.md` (디자이너는 `src/render/village/`, 나는 `src/village/`).

## 1단계 — 데이터 모델 (완료)
- `src/village/catalog.ts`: 가구 12종(시범 PASS 6 + 새 6), 색 2–3, 동기화 비트 = 번호 × 4 + 색, 서랍 탭 5개, 주민 5명(이사 일수·대표 가구·선물 발신 여부).
- `src/village/model.ts`: 모두 유도값이다(저장하는 카운터 없음).
  - 누적 밝힌 날 = `v.pd` ∪ 데일리 기록(오늘까지). 마을 이전 플레이어(판은 풀었는데 pd 없음)는 최소 1일.
  - 방울 = 판 1개 + 데일리 3개. 병 = 처음 3병은 3방울, 그 뒤 6방울마다.
  - 우편 id: 이사 편지 0–15(주민 번호), 병 j = 16 + j − 1 → 기기끼리 같다. 연 편지 = `v.lr` = 그 가구를 가짐.
  - 하루 편지 1통: 그날 첫 우편만 편지, 나머지는 꼬리표 달린 선물(`deliver`, 기기 로컬 캐시). 첫날은 Momo 이사 편지가 편지, Wick 등불은 꼬리표("One more, for the room.").
  - 우편함 10통 초과분은 열 때 오래된 것부터 보관(= 열림 처리, 가구는 가짐).
  - 우정 0–5 = 이사 온 날부터 대화한 날 수(부탁 +2는 1.1). 임계 0/2/5/9/14/21.
  - 방 1개 18칸(바닥 3줄 × 5 + 벽 3) + 러그 층 + 벽지·바닥. 침대는 2칸. 같은 가구(색 포함)는 한 번만 놓인다. 40자 코드.
- `src/village/vstate.ts`: 동기화 `v`. 비트 집합 pd·ch·lr·u(+1.1 예약 mk·q·w)는 OR, 방은 방 단위 LWW (n, at, dev, s). n = 본 것 중 최대 + 1(램포트), at = max(시계, 본 at + 1) → 시계를 되돌려도 "보고 나서 한 편집"이 항상 이긴다. 미래 at은 now로 자른다.
- 테스트 `tests/village-model.test.ts` 20개: 30일 공백 뒤 감소 0, 하루 편지 1통, 방 규칙, 비트 코덱 퍼즈, 시계 역행 LWW(G7) 퍼즈 300회.
- 설계와 다른 점: `v.lr`의 편지 id는 "계기 + 날짜"가 아니라 "이사 주민 번호 / 병 번호"로 정했다. 병이 언제 찼는지는 진행 수치에서 알 수 없고(날짜별 방울 기록 없음), 번호는 모든 기기에서 같다. 편지인지 꼬리표인지, 병 선물을 누가 보냈는지는 기기 로컬 캐시다(동기화하지 않음, 다른 기기에서는 다르게 보일 수 있음 — 작은 관대함).

## 2단계 — 동기화 `v` (완료, G7)
- `src/sync/model.ts`: `SyncState.v`(빈 값 = `emptyV()`), `mergeStates`가 `mergeV`, `Plan.v`(달라졌을 때만), 와이어 키는 **`vl`**(와이어의 `v`는 이미 버전 번호 `v: 1`이라 옛 빌드가 검사한다 — 같은 이름을 쓰면 옛 빌드가 새 스냅숏을 통째로 버린다). 비어 있으면 바이트 0. 예산 트리밍에서 `v`는 자르지 않는다.
- `src/sync/index.ts covers()`에 `coversV` 추가(마을 비트를 가진 조용한 기기 키를 잘못 지우지 않게). `local.ts`: 스냅숏에 로컬 `v`, 계획 적용 때 `adoptSyncedV`(OR/LWW로 합침, 그 사이 로컬 편집 보존). `signal.ts`: 이유 `"village"`.
- 로컬 저장 `src/village/store.ts`(Preferences `village` = `{sv, loc}`): 직렬화된 쓰기, 동기 부분이 바뀌면 `syncSignal.dirty("village")`. 판을 풀면 `session.finishLevel`이 **동적 import**로 `noteLitDay(오늘)`(콜드 스타트 경로 0).
- 방 레코드의 기기 id는 앞 8자(동률 깨기 전용, 바이트 절약).
- 테스트 `tests/village-sync.test.ts`: **최대 상태 1,992 B ≤ 2 KB**(방 8개 × 18칸 + 러그, 비트 집합 5종 × 2년에 걸친 격일 365일, 읽은 편지 2,000통 격번, 해금 256비트 — 설계 문서 예시보다 가혹), 실제 헤비 1년 < 200 B, 예산 300 B로 줄여도 `v` 유지, 옛 스냅숏(무 `vl`) 디코드, 시계 역행 종단 테스트. 기존 sync 테스트 54개 그대로 통과.

## 3단계 — 장면 골격 (완료)
- `src/village/index.ts`(정적 진입은 동적 import뿐) → `VillageScene.ts`(지연 청크 41 KB) + 대사 JSON 청크(en 6.6 KB, ko 5.4 KB) + 키트 청크.
- 화면: 마을(배경+집 한 장, 주민 이미지 = `ambient()` 숨쉬기, 우편함 앰버 깃발, 등불 병 n/size, 돌아가기) → 대사 카드(이름표 위, 1–3줄 가변 높이) → 우편함 → 편지(종이·줄·글 하나의 변환) → 선물 공개(꼬리표 줄) → "내 오두막에 놓기"(앞줄 가운데부터 빈 칸 자동, 꽉 차면 서랍) / "나중에"(서랍에 앰버 점) → 방(18칸 + 러그 칩) → 서랍(탭 5, 색 점, 잠긴 카드 = 실제 그림 실루엣 + 이름 + "이사 선물: Luna"/"등불 병 선물로 와요", 칸 종류에 맞는 것만).
- 진입: 왼쪽 HUD 원판(캡션 "마을")이 마을을 연다. **골목 띠(alley)는 그대로 거리(town, 기념 판)를 연다** — 기존 e2e의 거리 테스트 6곳은 `alley`로 바꿨다. 마일스톤 방문(5·10판)도 거리 그대로.
- 첫 방문: Wick 호스트 2줄. 이후 소식 순서: 새 이웃 > 내일 이사 > 우편.
- 디자이너 키트(`src/render/village`)가 작업 중에 들어왔다. 로더가 코드 수정 없이 받아 쓰고, 키트의 `villageLayout`·`roomGeometry`로 집·우편함·칸 자리를 맞췄다. 계약 문서 §5에 장면 쪽 약속을 적었다(대사 카드는 마을에서 위쪽).

## 6단계 — 성능 (G5)
- 콜드 스타트 A/B(Chromium CPU ×4, 393×852 @3x, 교차 n=10, `playtest/wick-v12/coldstart.mjs`; A = 같은 트리에서 마을 연결 3곳만 되돌린 빌드): 돌아온 플레이어 interactive 중앙값 **737 → 732 ms (−5)**, 첫 탭 6.9 → 5.3 ms; 첫 실행 677 → 668 ms (−9). 게이트 +20 ms 이내(잡음 수준).
  - 메모: 키트의 `lanternHouse.ts`가 퍼즐 화면과 마을 청크 양쪽에서 쓰여 별도 청크로 갈라졌다(첫 화면 정적 import가 하나 늘어남). 측정상 영향 없음.
- 마을 열기(탭 → 마을 첫 프레임, `playtest/perf/village-open.mjs`, CPU ×4):
  - 처음 측정: 650 ms(데이터 150–280 ms + 키트 배경 래스터 ≈ 250 ms가 대부분, 굽기 기록 자체는 20–35 ms).
  - 대책: ① 실행 6 초 뒤(첫 실행 20 초) 유휴 프리웜 — 장면·키트·대사 청크, 저장, 기기 id, 그리고 **배경+집 층을 미리 굽고 래스터까지 강제**(1 px 읽기) ② 따뜻하면 탭과 같은 태스크에서 장면 추가(데일리 로그 `logNow()`, `peekVillage()` 동기 조회) ③ 래스터된 배경 사본 1장(≈ 5 MB)을 열기 사이에 보관.
  - 결과: 프리웜 뒤 첫 열기 **중앙값 56 / p75 57 ms**, 다시 열기 29 / 30 ms. 프리웜 전(실행 2.5 초 안에 탭) 564 ms. 실기기 p75 ≤ 400 ms는 기기에서 다시 재야 한다(측정 못 함).
- 대기 프레임: `scripts/idle-movers.mjs`에 village·room 시나리오 추가 → 둘 다 ambient 20 fps, 움직이는 비주변 객체 0.

## 7단계 — 아트 엔지니어 요청 반영 (완료)
- e2e `village.spec.ts:29`의 실패 원인: VoiceOver 층은 rAF 한 번에 묶어 갱신하는데, 화면 전환 직후 라벨을 한 번만 읽었다(경쟁). 회귀가 아니다 — 라벨 검사를 모두 `expect.poll`로 바꿨다. chromium + webkit에서 village·places·smoke 38개 통과.
- 편지: 키트 `drawLetterPaper`(바로 선 종이) + `letterLines` 기준선 위에 글을 놓는다. 글꼴은 `loadVillageFont(lang, "letter")`(DuskwickHand 서브셋)로 재고 그린다. 한국어(Gaegu)는 ×1.15. 글 폭 = 종이 괘선 범위(82 %). 실제 글꼴 G3 검사(e2e)도 편지는 손글씨 글꼴로 잰다. 키트가 없으면 예전 종이로 대체.
- 말하는 주민 머리 위 감정 말풍선: 키트 `residentHead()` + `drawEmote()`(Momo·우정 2+ 하트, Sage zzz, Luna 별, 그 밖 음표).
- 서랍 카드 `fit: "card"`, 선물 공개도 `"card"`, 방은 기본 `"room"`.
- 로더는 키트의 `villageArt` 외에 `villageLayout`·`roomGeometry`·`drawLetterPaper`·`letterLines`·`letterHeight`·`loadVillageFont`·`residentHead`·`drawEmote`를 이름으로 받아 합친다(없으면 자리 표시).
- ja/zh 실제 대사가 들어오면 `apps/client/scripts/subset-letter-fonts.py`를 다시 돌려야 한다(l10n TODO 문서에 추가).

## 8단계 — Reality G1(실제 빌드) 지적 반영 + 10개 로캘 연결 (완료)
- **G3 단어 잘림(#18) 원인**: 균형 줄바꿈이 줄 폭을 줄여 가며 시험할 때, "글자 단위 자르기" 대체 경로가 라틴 단어 안에서도 켜져 "Arche / d chair"를 2줄 해로 받아들였다. 노드 폭 모델과 실제 글꼴 검사 모두 "넘침"만 보고 "단어 보존"은 보지 않아 거짓 통과가 됐다.

## 14. 알림 소프트 질문: 시점이 아니라 상태로

- **원인**(`LanternsScene.afterCountedDaily`/`leaveDaily`): 질문은 메모리 콜백 `pendingAsk`였고, 트랙 복귀 콜백이 그것을 한 번만 읽었다. 그래서 두 가지가 생겼다.
  - 권한 확인이 복귀보다 늦게 끝나면 질문이 조용히 사라졌다.
  - 일찍 끝나면 700 ms 타이머로 떴다. 이때 판을 누르던 손가락에 걸리면 바깥 탭이 곧 "나중에"가 되어, 다시는 묻지 않았다.
  - 오너의 "알림창이 안 나왔다"는 이 둘 중 하나로 설명된다. 기기 로그가 없어 단정하지는 않는다. e2e에서는 트랙이 먼저 돌아오는 경우가 실제로 재현된다(`pend` 없음 확인).
- **수정**:
  - `notify.markAsk(minute)`가 대기 상태(`pend`)를 저장한다. `later()`/`enable()`이 답할 때 지운다. 실행할 때는 `pendingAsk()`로 다시 읽는다.
  - 씬의 `stepNotifyAsk`가 매 프레임 조건을 본다. 트랙이고(데일리 아님), 시트·카드·질문·튜토리얼·가이드·밤 장면·광고 칩이 없고, 손가락이 닿아 있지 않아야 한다. 또 입력이 1.5 s 이상 없고, 거버너가 전체 속도가 아니어야 한다. 이 조건이 맞으면 실행당 한 번 띄운다.
  - 거버너가 계속 깨어 있으면 8 s 무입력 뒤에 띄운다. 그래도 남으면 다음 실행 때 띄운다.
  - 카드가 열려 있는 동안 판 탭은 기존 라우팅(`down = "ask"`)이 삼킨다. 수는 생기지 않는다.
- **확인**:
  - 새 `e2e/notify-ask.spec.ts`(빠른 복귀 + 플레이 중 대기, 느린 복귀 + 재실행 재표시 + 답 뒤 없음)
  - `flow`·`i18n`, 그리고 `E2E_PORT=4449`에서 sync·daily·smoke·village 50/50(chromium + webkit)
  - 클라이언트 유닛 538
