# 초보자 첫 사용 테스트 (2026-10-17)

> **요약**
> - 지금 빌드는 진짜 초보자가 혼자 규칙을 알아내기 어렵다.
> - 규칙 7개 가운데 화면에서 보여 주는 것은 4개다. 그나마 보여 주는 것도 대부분 "한 번 보고 지나가는 시범"이다.
> - 플레이어가 화면을 한 번 누르면 시범이 바로 사라진다(`LanternsScene.ts:1516`, `moves.length === 0` 조건).
> - 첫 판에 이미 숫자 돌(1, 2, 4)이 나오는데, 숫자의 뜻은 2판에서야 가르친다.
> - 내 첫 탭이 정답이 아니면 1초 안에 실 모양 줄과 깨진 별 표시(막힘 표시)가 뜬다. 숫자를 배우기도 전에 "틀렸다"는 표시부터 받는다.
> - 오류는 색과 기호(✕, 산호색 테두리, "−등불" 알약, 깨진 별, 실)로만 알린다. 그 이유는 어디에도 쓰여 있지 않다.
> - 결론: **짧은 글 안내(한 줄 ≤ 8단어) + 직접 해 보는 튜토리얼 + 언제든 열 수 있는 "?" 규칙 카드 + 실수했을 때 이유를 말해 주는 한 줄**. 이 네 가지가 필요하다. 규칙 코어는 건드리지 않는다.

- 근거:
  - 실제 빌드(`vite build --mode e2e`)를 Playwright로 빈 저장소 상태에서 직접 조작했다.
  - 화면 크기와 언어는 iPhone 15(393×852)와 iPhone SE(375×667), en-US와 ko-KR. 엔진은 Chromium, SE ko는 WebKit.
  - 스크린샷 128장은 `playtest/shots/novice/`에 있다. 구동 스크립트는 `playtest/novice/run.mjs`다.
  - 테스트 브리지(`window.__e2e`)는 탭할 좌표와 정답·오답 칸을 알아내는 데만 썼다. 화면은 사용자가 보는 그대로다.
- 한계:
  - 페르소나는 AI가 시뮬레이션한 것이다. 실제 사람 데이터는 0이다.
  - 소리와 햅틱은 확인하지 않았다.
  - 시뮬레이터와 실기기의 체감 속도는 확인하지 않았다(스크린샷 저장 때문에 화면 간 시간이 실제보다 길다).
  - UMP/ATT 동의 팝업은 웹 빌드에 없어서 확인하지 못했다.

## 1. 실제 첫 10분 흐름 (스크린샷)

파일 이름의 접두어는 화면 크기와 언어다. `en15-` = iPhone 15·영어, `ko15-` = iPhone 15·한국어, `enSE-`/`koSE-` = SE.

| # | 장면 | 파일 | 화면에 실제로 보이는 것 |
|---|---|---|---|
| 1 | 첫 프레임 0.25 s | `en15-01` | 단색 보라 그라데이션. 로고와 글자 없음 |
| 2 | 0.75–2.2 s | `en15-02`, `03` | 집 + HUD + 3×3 "목표 카드". 손가락이 "4" 돌 둘레에 등불 4개를 놓는다 |
| 3 | 목표 카드 2회 반복(약 10 s) | `en15-04`–`06` | 등불 4개, 4가 금색으로 변함, 집 창문이 켜짐. **빛줄기가 퍼지는 모습은 없다**(3×3이라 칸이 다 붙어 있음) |
| 4 | 1판 탭 시범 | `en15-07`–`10` | 5×5 판, 숫자 돌 1·2·4와 숫자 없는 돌. 손가락이 한 칸을 탭하면 등불이 놓이고 십자로 빛이 퍼진다 |
| 5 | 돌을 눌러 봄 | `en15-11` | **아무 반응 없음.** 손가락 시범도 사라진다 |
| 6 | 첫 탭(정답 아닌 칸) | `en15-12`, `13` | 등불과 빛은 좋다. 그런데 1.2 s 뒤 **실 모양 줄이 "2" 돌로 이어지고 깨진 별이 붙는다**. 무슨 뜻인지 설명이 없다 |
| 7 | 같은 줄에 두 번째 등불 | `en15-14`–`16` | 두 등불에 산호색 테두리와 ✕, 동시에 "4"로 가는 실 하나 더. 4 s를 기다려도 "하나 빼라"는 손가락이 나오지 않는다(막힘 표시가 떠 있으면 안내가 막힘, `:1512`) |
| 8 | 숫자 초과 | `en15-18`, `19` | 화면에 오류 신호 4종이 한꺼번에: 테두리, ✕, "2"가 산호색으로 변하고 "−🏮" 알약, 실과 깨진 별 |
| 9 | 힌트 | `en15-23`–`25` | 힌트 버튼이 "등불 + 산호색 둥근 화살표"로 바뀌고 틀린 등불 위에도 같은 화살표가 뜬다. 한 번 더 누르면 앱이 대신 빼 준다. 화살표가 "빼라"인지 "새로고침"인지 알 수 없다 |
| 10 | 1판 완성 | `en15-26`–`31` | 숫자가 금색, 창문 점등, 약 2 s 뒤 다음 집. "다 됐다"는 말이나 멈춤이 없다. 2 s 뒤에는 이미 다음 판 시범 손가락이 나와 있다 |
| 11 | 2판 숫자 시범 | `en15-33`–`37` | 손가락이 "3" 둘레에 등불 3개를 놓고 3이 금색. 이어서 "0"을 가리킨다. 손가락이 숫자를 가린다(`en15-36`). 한 바퀴에 약 9 s |
| 12 | 0 옆에 등불 | `en15-38`, `39` | "0"이 산호색, "−🏮" 알약. 이유 문장 없음 |
| 13 | 3판 충돌 시범 | `en15-42`–`45` | 첫 등불, 같은 줄의 두 번째 등불, ✕, 다시 걷기. **"돌이 사이에 있으면 괜찮다"는 내용은 없다** |
| 14 | 4판 오늘 버튼 손가락 | `en15-47`–`49` | 달력 "16"을 손가락이 탭한다. 무엇인지 글이 없다 |
| 15 | 데일리 | `en15-50` | 첫날 데일리가 **6×6**이다(지금까지는 5×5). 위에 "< 🏠" 칩이 있고, 거리 버튼은 흐리게 보인다 |
| 16 | 결과 시트 | `en15-51`, `52` | 달력 16, ⏱ 0:11, ✨, 🔥 1, 파란 리본 등불 2개, 점 30개 줄, **금테 공유 버튼이 주 버튼**, 집 버튼. 글자는 하나도 없다 |
| 17 | 집으로 | `en15-53`, `54` | 화면이 어두워지는 1–2 s(밤 연출) |
| 18 | 거리(마을) | `en15-55`, `56` | 화면 위 60 %가 빈 하늘. 집 2·3, 홈 버튼. 이 화면이 무엇인지 설명이 없다 |
| 19 | 설정 | `en15-57`, `koSE-20` | **앱에서 글자가 있는 유일한 화면**(소리·숫자·공유에 시간·진동·매일 알림·안내·처음부터·개인정보). 닫기 버튼 없음(끌어 내리는 손잡이만 있음). "규칙 보기"가 없다 |
| 20 | 5판 뒤 | `en15-58`–`62` | 가로등 들르기, 위쪽 등불 줄에 5개 켜짐. 줄의 의미(10판 = 골목 하나)는 설명이 없다 |

SE와 한국어(`enSE-*`, `koSE-*`, `ko15-*`)도 흐름이 같다. 게임 화면에 글자가 없으니 한국어 사용자가 얻는 것도 설정 화면 캡션뿐이다. SE에서 충돌이 나면 ✕ 3개, 테두리 3개, 실 1개가 5×5 판을 덮는다(`enSE-12`).

## 5. 고칠 것 (스펙)

원칙:
1. **규칙 하나에 한 단계.** 한 줄 ≤ 8단어, 한 화면 ≤ 2줄.
2. **직접 해 보며 배운다.** 손가락이 가리키는 곳을 플레이어가 직접 탭해야 넘어간다(강제 첫 수).
3. **실수는 이유를 말해 준다.** 색과 기호는 그대로 두고 한 줄 문장을 더한다.
4. **규칙은 언제든 "?"에서 다시 볼 수 있다.**
5. 규칙 코어(`games/lanterns-pips`)는 그대로 둔다. 튜토리얼 판은 클라이언트의 고정 레벨 문자열로 만들고, 같은 `apply` 규칙으로 돌린다.

### 5-A. 직접 해 보는 튜토리얼 "첫 마당" (약 45–70 s, 1판 앞)

- 지금의 목표 카드와 1판 탭 시범을 이것으로 대체한다.
- 작은 판 4개를 쓴다.
- 각 판은 **성공해야만 다음으로** 넘어간다.
- 넘어갈 때마다 짧은 축하를 넣는다: 판이 금빛으로 변하고 창문이 하나 켜지며 "좋아요!" 0.6 s.
- 판 표기: `.` 바닥, `#` 돌, 숫자는 숫자 돌, `L` 미리 놓인 등불.

**공통 화면 구조**
- **안내 띠**: 판 바로 위, 집 아래 HUD 줄 자리에 놓는다.
  - 크림색 바탕(`PAL` 문패색)에 진한 남색 글자. 크기는 20 pt 이상이고 Dynamic Type 배율 k를 따른다(`UX-AUDIT` 6번).
  - 엄지가 닿고 판과 가까워 시선 이동이 적은 자리다.
  - 튜토리얼 동안 HUD 4버튼은 숨긴다. 선택지는 판 하나뿐이다.
- **강조**: 목표 칸만 밝게 두고, 나머지 판은 40 % 어둡게 덮는다. 목표 칸에는 숨쉬는 금색 테두리를 두른다.
- **손가락**: 지금의 `Guide.finger`를 그대로 쓴다. 목표 칸 **옆**에서 탭하고, 숫자 위에는 절대 올리지 않는다(C26).
- **건너뛰기**: 오른쪽 위에 "건너뛰기 / Skip" 글자 버튼(44 pt)을 둔다. 두 번째 설치부터, 또는 설정 > 처음부터를 거친 뒤에만 보인다. 첫 설치에는 숨긴다.
- **적응 규칙** (모든 단계에 공통):
  - 엉뚱한 칸을 탭하면 그 수는 적용하지 않는다(튜토리얼 판에서는 막는다). 칸이 살짝 흔들리고 안내 띠 2줄째에 단계별 "오답 문구"가 2.5 s 뜬다. 손가락이 다시 시범을 보인다.
  - 같은 단계에서 오답이 2번이면 손가락이 직접 놓아 준다(자동 진행). 다음 단계부터 손가락이 0.5 s 먼저 나온다.
  - 6 s 동안 입력이 없으면 손가락이 다시 나온다(지금 2.5 s는 너무 빠르다. P4는 읽는 중이다).
  - VoiceOver가 켜져 있으면 안내 띠 문장을 그대로 읽어 준다(a11y 레이어에 `tut.*` 키를 추가).

**판 설계 메모**
- T1–T5는 모두 손으로 만든 판이다. 해가 여러 개여도 튜토리얼에서는 "모든 칸 켜짐 ∧ 충돌 0 ∧ 숫자 일치"만 확인하면 된다.
- T3와 T4의 정답 판정은 기존 `analysis()`를 그대로 쓴다.
- 레벨 텍스트는 `games/lanterns-pips/level.ts` 형식을 쓴다. 규칙 코드는 바꾸지 않는다.

**튜토리얼 뒤의 실제 판(1–3판)**
- 지금의 숫자 시범(2판)과 충돌 시범(3판)은 **복습용 짧은 시범**으로 남긴다. 한 바퀴만 돌고, 같은 안내 띠 문장을 다시 쓴다.
- 플레이어가 탭해도 시범이 사라지지 않게 한다. 띠를 접어 판 위에 "?"로 남긴다.
- 1판은 지금 판(5×5, 숫자 1·2·4)을 그대로 써도 된다. 튜토리얼에서 숫자를 이미 배웠기 때문이다.
- 1–3판에서는 막힘 실을 끄고 아래 5-C의 한 줄 설명만 쓴다. 막힘 실은 4판부터 켠다.

**측정**: 튜토리얼 단계별 완료율, 오답 수, 건너뛰기율, 첫 3판 힌트 사용 수.
**목표** `[PLACEHOLDER]`: 튜토리얼 완료 ≥ 90 %, 1판 완료 ≥ 85 %.

### 5-B. "How to play / 게임 방법" 시트 ("?" 버튼)

**버튼**
- 위치: HUD 왼쪽 위, ⚙ 바로 오른쪽에 44 pt "?" 버튼(같은 원형 HUD 문법).
- 집, 탑, 데일리 화면에서 모두 같은 자리에 둔다.
- 처음 3판 동안 판이 2분 넘게 끝나지 않으면 "?"가 한 번 맥박친다.
- 설정의 "안내" 줄은 "게임 방법 / How to play"로 이름을 바꾸고 같은 시트를 연다. 기존의 "안내 다시 보기"는 시트 맨 아래 "Replay tutorial / 튜토리얼 다시 하기"로 옮긴다.

**시트 구성**
- 하단 시트, 높이 85 %. 위에 손잡이, **오른쪽 위에 "✕ 닫기" 버튼**을 둔다(C23).
- 카드 4장을 세로 스크롤로 보여 준다. 각 카드 = 3×3 또는 1×4 미니 판 애니메이션(2.5–4 s 반복, 동작 줄이기 상태에서는 마지막 프레임 정지 이미지) + 굵은 한 줄 + 작은 보조 한 줄.

| 카드 | 미니 판 애니메이션 | 굵은 줄 (en / ko) | 보조 줄 (en / ko) |
|---|---|---|---|
| 1 | 1×4 바닥. 손가락 탭 → 등불 → 빛이 줄을 따라 퍼짐 → 돌 하나에서 멈춤 | "Tap a tile to place a lantern." / "칸을 눌러 등불을 놓아요." | "Light shines until a stone." / "빛은 돌 앞까지 퍼져요." |
| 2 | 3×3. 마지막 어두운 칸이 켜지고 판 전체 금빛, 창문 점등 | "Light up every tile." / "모든 칸을 밝혀요." | "Tap a lantern to remove it." / "등불을 다시 누르면 빠져요." |
| 3 | 같은 줄 등불 2개 → ✕ → 사이에 돌이 생기면 ✕가 사라지고 ✓ | "Lanterns can't shine on each other." / "등불끼리 서로 비추면 안 돼요." | "A stone between them is fine." / "사이에 돌이 있으면 괜찮아요." |

### 5-C. 판 안 오류 설명 ("왜"를 말하는 한 줄)

**동작**
- 표시 자리: 판 바로 위 안내 띠(튜토리얼과 같은 컴포넌트).
- 표시 시점: 오류가 생기고 0.9 s 뒤에 띄운다(지금의 막힘 지연과 맞춤). 그 사이에 입력이 있으면 취소한다. 2.8 s 동안 보인 뒤 사라진다.
- **오류는 한 번에 하나만** 보여 준다. 우선순위: 충돌 > 숫자 초과 > 0 위반 > 막힘(채울 수 없음) > 다 켰는데 숫자가 틀림.
- 같은 종류는 한 판에 한 번만 띄운다. 이후에는 아이콘만 남긴다. 처음 10판이 지나면 "?" 시트와 힌트에서만 문장을 쓴다(설정에서 "도움말 문장 항상 보기" 켜기 가능).
- 기존 시각 신호는 지금처럼 그린다. 단 한 번에 하나만 강조한다. 나머지는 50 % 흐리게 한다(C6).

| 상황 (판정 소스) | en | ko | 함께 보이는 것 |
|---|---|---|---|
| 두 등불이 서로 봄 (`analysis().conflicts`) | "Lanterns can't shine on each other." | "등불끼리 서로 비추면 안 돼요." | 두 등불 사이에 빛줄기를 산호색으로 그림 + ✕ |
| 숫자 초과 (`cell.over`) | "Too many lanterns by this {n}." | "이 {n} 옆에 등불이 너무 많아요." | 해당 돌 테두리 + "−🏮" |
| 0 옆 등불 | "0 means no lanterns beside it." | "0 옆에는 등불을 두지 않아요." | 0 돌 테두리 |

- 이 문장들 대부분은 VoiceOver 문자열(`a11y/strings.ts`의 `ann.conflict`, `cell.over`, `cell.stuck`)에 이미 있다. **보이는 문자열로 승격**하고 7개 언어 번역만 다듬으면 된다.

## 6. 우선순위 (구현 순서 제안)

1. **5-C 오류 한 줄 + 한 번에 하나만 강조**(D14). 문자열이 거의 이미 있다. 비용은 낮고 효과는 가장 크다.
2. **5-A 튜토리얼 T1–T4(+T5)**: 1판 앞에 넣는다. 1–3판에서는 막힘 실을 끈다.
3. **5-B "?" 시트**: 카드 4장, 설정 "안내" 교체.
4. **D1 HUD 캡션, D2 완성 문구, D3 결과 시트 글자.**
5. D4–D14.

검증:
- 실제 사람 5명(35–60세, 논리 퍼즐 경험 없음)에게 설명 없이 폰을 건넨다.
- 첫 3판 동안 말하면서 하게 한다(think-aloud).
- 기록: 규칙 7개를 자기 말로 설명할 수 있는지, 첫 3판 힌트 수, 그만둔 지점.
- 이번 문서의 C1–C31을 체크리스트로 쓴다.

**"broken"의 정의**(이것이 보이면 실패):
- 5명 중 2명 이상이 1판에서 "뭘 해야 해?"라고 묻는다.
- 2명 이상이 숫자 규칙을 "대각선 포함"이나 "남은 수"로 설명한다.
- 2명 이상이 결과 시트에서 공유를 누른다.
