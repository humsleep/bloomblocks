## (a) 가장 약한 주장 3개와 반론

### 1. Reality §1 요인 5: "Akari 앱 평점 수(28·3·1개)는 수요가 거의 없다는 시장 신호다"

**왜 약한가**: 같은 팀의 market 문서가 이 추론을 반박한다.
- 같은 규칙(Star Battle/Queens)을 쓰는 클론은 평가가 889개다("Queens: Board Puzzle Games").
- Meowdoku는 33.6만 개다(market §1-1, §1 교훈 1).
- **규칙이 같아도 평점 수는 유통(UA·플랫폼)에 비례했다.**
- 따라서 Akari 앱의 평점이 적다는 것은 "Akari 수요가 없다"가 아니라 "UA도 아트도 없는 Akari 앱에는 아무도 오지 않았다"는 뜻이다. Duskwick의 상황과 같은 변수(유통)를 가리킬 뿐, 장르 천장의 증거가 아니다.

**남는 진짜 위험**
- 규칙 수(7개)와 "숫자 = 계산" 공포다. 이것은 평점 수가 아니라 **사람 FTUE 측정**으로만 판정할 수 있다.
- Reality의 게이트 A(FTUE ≥ 80 %, n ≥ 20)에 전적으로 동의한다.

### 2. Visual §5.8: "친구 7명 = 일주일." 해금 조건은 3일 연속 / 집 10채 / 7일 연속 / 힌트 없이 5판 / 가을 / 겨울

**문제 세 가지**
1. **놓친 날을 벌한다.** "3일 연속·7일 연속"은 하루를 놓치면 진행이 0이 된다.
   - 이 타깃(교대 근무, 아이)이 가장 많이 이탈하는 지점에 수집 보상까지 같이 빼앗긴다.
   - 보호막이 덮어 주는 날도 있지만, 월 2개를 넘기면 끊긴다.
2. **"힌트 없이 5판"은 힌트 무료 원칙에 반한다.** 힌트를 쓰면 귀여운 친구를 못 받는다는 신호가 된다.
   - Good Sudoku식 "힌트로 배운다" 철학을 깨고, 초보(NOVICE P1·P3: 힌트 의존)를 차별한다.
3. **수집이 너무 빨리 끝난다.** 계절 둘을 빼면 5명이 7–10일 안에 끝난다. D30·D90에 남는 수집 동기가 0이다.
   - 수집 메타의 목적(장기 리텐션)과 맞지 않는다.

**함께 약한 근거**: "B+가 8.3점"은 디자인한 모델이 직접 매긴 점수다. 문서도 이를 인정한다. 형태 결정(B+)에는 반대하지 않는다. 오독 IoU 근거가 더 낫다.

### 3. Growth P-2: "웹 데일리는 출시 전 필수(5–8일)"

**문제 세 가지**
1. **데일리 위주 45 %를 앱 밖으로 빼낸다.**
   - 이 집단의 핵심 가치(매일 한 판, 공유)를 웹이 설치 없이, 광고 0으로 다 준다. 그러면 앱을 설치할 이유도, 남을 이유도 사라진다.
   - Wordle은 앱이 없었으니 잠식할 것도 없었다. 우리는 앱이 수익원이다.
2. **효과 추정이 근거 없이 넓다.** 웹 루프 k_web 0.2–0.8은 "불확실"로 표기돼 있다. 웹 → 앱 전환 3–10 %도 추측이다.
   - 같은 문서가 공유 루프를 "엔진이 아니라 확성기"라고 결론 내렸다. 그런데도 출시 전 5–8일을 쓰자는 것은 앞뒤가 맞지 않는다.
3. **출시 전 일정과 경쟁한다.** 출시 전 우선순위는 Reality P1 결함 1–8번, FTUE 측정, Wick이다. 웹 데일리는 앱 심사와 무관한 별도 산출물이다.

**반론**
- 출시 전에는 P-1(공유 문구에 링크)과 P-3(답을 가린 엽서 이미지)만 한다. 둘을 합쳐 3–3.5일이다.
- 웹 데일리는 **맛보기 형태로 1.1 이후**에 낸다(아래 (b)-2).

**덧붙임 (4번째 후보)**
- market §3-4는 차트 시도 시기를 "2026-10 말–11 초"로 제안한다.
- 그러나 ASC 레코드, 실제 AdMob ID, 사람 테스트가 0인 현재 상태로는 일정상 불가능하다.
- 같은 문서가 연말을 피하라고 했으므로, 차트 시도는 **2027-02 원소절(ASO §4.2)** 하나로 모은다.

## (b) 계획 통합

### (b)-1. Wick 친구 해금 — 하나의 규칙: "등불 켠 날" 누적

**규칙**
- 카운터 `litDays` = 판을 하나라도 푼 **서로 다른 날짜 수**다.
  - 데일리든, 집이든, 탑이든, 지난 날 판이든 상관없이, 그날 무언가를 풀었으면 1이 늘어난다.
- **절대 줄지 않는다. 연속을 요구하지 않는다. 힌트·시간 조건이 없다.**
- 하루에 몰아서 해도 +1뿐이다. 그래서 갈아 넣기(grind)도, 돈으로 사는 길도 없다.
- 상태는 기존 데일리·진행 날짜 기록에서 유도한다. iCloud 날짜 합집합 병합을 그대로 쓰므로 **새 동기화 키가 0**이다.
  - 트랙 판의 날짜 집합이 아직 없다면 날짜 집합 하나를 추가한다. 형식은 기존 패턴과 같다.

**정규 친구 일정 `[P]`** (visual 팔레트와 성격을 그대로 쓴다)

| litDays | 친구 | 근거 |
|---|---|---|
| 0 | Wick | 튜토리얼에서 만난다 |
| 2 | Momo | D1 고리. 결과 엽서에 "내일 누군가 와요" 실루엣을 띄운다 |
| 4 | Sage | |
| 7 | Luna | 7일 선물(광고 없는 1시간)을 대체한다 |
| 10 | Pip | |
| 14 → 20 → 27 → 35 → 45 → 60 → 75 → 90 | 1.1에 추가할 친구 8명 | visual에 같은 리그(팔레트·불꽃·소품 1)로 8명 추가 디자인을 요청한다 |

**계절 친구 (Kuri 가을, Yuki 겨울)**
- 축제 판 7개를 끝내면 받는다. 판은 열린 날부터 축제 끝까지 아무 때나 풀 수 있다(만회 가능).
- 놓치면 **내년 같은 축제에 다시** 나온다.

**폐기·변경**
- 연속 3일·7일 조건, 집 10채 조건(집 진행은 마을 꾸밈 레일이 맡는다), 힌트 없이 5판 조건은 모두 없앤다.
- 스트릭은 🔥, 이정표, 엽서 테두리 같은 **표시와 축하로만** 남긴다. 보상과 묶지 않는다.

**오늘의 손님**
- 손님 = `hash(날짜) mod 해금한 친구 수`다. 직전 2일과 같은 손님은 피한다.
- 엽서 우표와 알림 문구에 쓴다.

**ASO 평점 요청 조건 수정**
- "7일 선물 상자를 연 뒤" → **"친구 도착 연출 뒤"**로 바꾼다.
- "판 10개 미만 금지" → **"litDays < 3 금지"**로 바꾼다. 하루 1판인 데일리 위주 사용자를 빼지 않기 위해서다.

### (b)-2. Growth의 공유·웹과 맞추기

**공유 카드(앱) = 엽서 이미지 1장 + 텍스트 2줄 + 링크(P-1, ct 토큰)**
- 판은 **풀기 전 상태**(돌과 숫자만)로 넣는다. growth의 스포일러 지적이 옳다. 내 r1-design §3.8의 "등불 배치(색 블록)"는 철회한다.
- 우표 = 오늘의 손님, 소인 = #n과 달.
- P-4 "경로 띠"(🟥 = 실수)는 넣지 않는다. 이 타깃이 자기 실수를 공개하고 싶어 할 근거가 없다. 출시 뒤 A/B 후보로만 남긴다.

**웹 데일리(1.1 이후) = 맛보기**
- 제공하는 것: 오늘의 판 하나, Wick 반응, 공유.
- 제공하지 않는 것: **연속 기록, 친구, 손님, 지난 날, 마을.**
- 결과 화면 CTA는 "연속 기록과 Wick의 친구들은 앱에서"다(Smart App Banner + ct).
- 웹이 데일리를 대체하지 않고, 앱으로 데려오는 문이 되게 한다.

### (b)-3. Reality의 "사람 데이터 전에는 메타를 늘리지 말라"와 맞추기

**동의하는 부분**
- FTUE와 P1 결함이 1순위다.
- 측정 계측(TestFlight 로컬 로그)이 없으면 무엇도 판정할 수 없다.
- 달력 트로피, 꾸밈 선택, 계절 축제 같은 새 시스템은 **사람 게이트 뒤로 미룬다.**

**동의하지 않는 부분**: 출시 전에 장기 고리를 전부 빼자는 것.
1. TestFlight 20명으로는 D7·D30을 잴 수 없다(기간과 표본이 모두 부족하다). "데이터를 보고 넣는다"면 장기 고리는 영원히 들어가지 않는다.
2. 출시 코호트(예약 주문, 피처링, 출시 주 콘텐츠)가 평생 가장 큰 코호트다. 그 코호트를 스트릭 하나로만 붙잡는 것은 확인된 약점을 그대로 출시하는 셈이다.
3. 친구 레일 v1은 **새 시스템이라기보다 기존 보상(7일 선물)을 대체하는 것**이다. 데이터에서 유도하므로 상태 비용이 없고, 3일이면 된다.

**절충**
- 1.0에는 "대체하는 것 + 공유·스토어에 필요한 것 + 기존 데이터로 유도되는 것"만 넣는다.
- 순서: TestFlight 1차(FTUE) → 통과하면 친구 레일·엽서 → 2차(D1 대용 지표).
